# 《天台夜班》UI 三方向初稿共同规范

## 项目与目标

这是现有静态 HTML/CSS/JavaScript 鼠标解谜游戏《天台夜班》的视觉重塑初稿，不更改谜题规则、道具交接协议和通关流程。玩家是深夜天台便利店的夜班员，先接待一位神秘客人，再依据小票和图纸进入仓库，装配并启动传送门。现有界面像深色后台：商品和组件都是矩形按钮，顾客只是双色剪影，场景缺少叙事焦点；仓库还出现内容挤在左侧、文字竖排、传送门被裁切的问题。此次目标是让玩家第一眼感到自己置身一个陈旧、安静、略带不安的手绘密室，而不是操作一套管理系统。

## 受众、场景与体验

面向喜欢《绣湖》《纸嫁衣》式氛围、点击观察与轻量道具解谜的玩家。主要使用笔记本或桌面浏览器，鼠标点击为主，拖放只是等效替代。正文不得小于 14px，标签不得小于 12px；交互目标清晰，不能只靠颜色表达状态。恐怖感来自人物视线、陈旧物件、留白和局部异常，不使用血腥画面、突发跳吓或持续闪烁。参考只提取手绘、舞台化构图、民俗旧物、克制悬疑等抽象特征，不复制参考作品的角色、场景、符号或素材。

## 初稿输出

- 每个方向一个完整、可直接打开的单文件 HTML，统一按 1440×900 截图。
- 同一屏内提供「营业区」「仓库」两个场景切换；默认营业区，仓库必须真实可见且布局完整。
- 营业区包含：雨夜窗、饭团/咖啡胶囊/电池及价签、神秘顾客与对话、小票、扫码器、咖啡机、纸杯、仓库门。
- 仓库包含：能源接口、稳定器、聚焦环及其真实物体轮廓；按「能源接口 → 稳定器 → 聚焦环 → 门框」从左到右排列的导管节点；波形校准；完整可见的传送门。
- 组件不能再用长方形按钮代替物体。能源接口应有插座/铜端子特征，稳定器应有线圈或配重结构，聚焦环应有同心环和镜片结构；安装轮廓与组件外形一致。
- 顾客必须使用共享人物素材 `assets/customer.jpg`，呈现明确人形与脸部，不得退回几何剪影。
- 保留标题《天台夜班》与时间 23:47，减少无意义 HUD、占位字样、状态数字和装饰性标签。

## 共同视觉约束

暗色必须有纸张、木材、金属、旧印刷或手绘肌理的依据，禁止通用蓝紫霓虹、玻璃拟态 Bento、圆角 SaaS 卡片、emoji 图标和廉价 glow。文字采用有编辑感的中文宋体/衬线标题与清晰正文组合，避免大面积等宽字体。每个方向要有不同的布局骨架，不只是换色。场景应有一个明确的视觉锚点：营业区优先顾客或仓库门，仓库优先传送门/机械装置。互动控件与场景物件在造型上统一，但可点击性要通过轻微高光、光标、焦点轮廓和反馈体现。

## 动作与动效分镜卡

仓库开门是用户要求的重点，正式实现采用一次约 1200–1500ms 的可中断非阻塞动画：

1. 触发：玩家输入正确三位密码；锁舌先短促回缩，门缝出现一线暖光或冷光。
2. 0–250ms：数字锁轻微震动后稳定，门把手下沉，门内仍保持黑暗。
3. 250–1050ms：门板绕左侧门轴以 `perspective` 与 `rotateY` 向内打开，门缝同步扩宽；门后只露出仓库局部，不展示下一世界。
4. 900–1400ms：门内货架/装配台由暗到明，粉尘或细小雨丝只做极轻一层，门停稳后切换仓库。
5. 反馈：配合既有解锁音效，不使用 alert，不锁定其他菜单；`prefers-reduced-motion` 下取消旋转和震动，仅做 100ms 透明度切换。

组件安装以吸附归位和一次短促高光确认；导管按顺序排布，当前待连接节点有明确呼吸式轮廓，连错只显示方向提示，不弹回整个布局。顾客可有极轻微眨眼或视线变化，但静态初稿必须先在无动画时也成立。

## 素材与交付

三版共用同一张原创顾客图，其他物件允许使用 HTML/CSS 与功能性的 inline SVG 轮廓。图片路径使用相对路径，确保 HTML 在本地服务中可直接访问。每版必须附截图，并检查浏览器控制台无错误。初稿是方向选择用途，不直接覆盖正式 `game/` 文件。
