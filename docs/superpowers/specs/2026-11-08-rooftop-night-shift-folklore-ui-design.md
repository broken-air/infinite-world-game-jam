# 《天台夜班》B 稿民俗密室 UI 设计

## 意图与已确认方向

将现有后台式界面改为 B 稿「民俗密室」：以旧木、暗红门、铜质机械、褪色纸张和局部灯光构成手绘悬疑场景。用户已查看 A/B/C 三套营业区与仓库真实截图并明确选择 B。参考《绣湖》《纸嫁衣》的抽象氛围，不复制角色、场景、符号或素材。

## 目标

- 营业区形成雨夜窗、货架、柜台人物、仓库门的完整舞台构图，顾客具有明确人形、脸部和对话关系。
- 仓库以大型传送门和机械装配为视觉锚点，组件与安装插槽采用一致的插座、线圈、同心环真实轮廓。
- 导管节点严格按能源接口 → 稳定器 → 聚焦环 → 门框从左到右排列，连接方向与图纸一致。
- 正确密码触发约 1200–1500ms 的非阻塞开门动画：锁舌、把手、门缝、门板透视、门内亮度依次变化，随后进入现有仓库场景。
- 修复文字竖排、内容挤压、右侧空荡、传送门裁切等现有构图问题，保留清晰焦点和减少动态效果支持。

## 非目标与约束

不改变商品价格、扫码顺序、密码、咖啡流程、遗物效果、组件/导管/旋钮判定、通关时长和官方交接协议。不新增死亡、跳吓、血腥、阻塞弹窗或外部运行依赖。保留现有付钱特写、空眼印记、图纸提示、音频与测试 testid。工作区已有未提交修改，必须逐段增量编辑，不回退、不删除无关改动，不用初稿文件覆盖正式实现。

## 方案比较

- A 夜班档案：信息清晰但编辑档案感强，削弱人物与门的叙事氛围。
- B 民俗密室：最贴近用户参考，能同时容纳人物、旧物和机械，已选定。
- C 纸偶剧场：舞台感鲜明，但与现有民俗细节及开门结构的衔接成本较高。

## 实现结构

继续复用 `store-scene.js`、`warehouse-scene.js` 的挂载与状态渲染，不新增平行场景系统。顾客图片使用原创本地资源并保留替代文本；商品、机器、组件和门使用 CSS 与功能性 inline SVG。开门动画由现有 `submitLock` 成功分支触发，动画结束才调用 `api.enterWarehouse()`；销毁场景时取消计时器，减少动态效果时缩短为透明度过渡。仓库节点顺序由单一数组驱动，SVG 连线坐标与节点布局共用同一位置定义。样式修复通过明确覆盖基础 `.scene` 网格约束实现，避免依赖追加样式的偶然顺序。

## 验收

现有单元与浏览器测试保持通过；补充顾客资源、真实组件轮廓、节点顺序、开门后进入仓库及减少动态效果检查。以桌面 1440×900 和现有测试视口检查营业区、仓库、付钱近景、开门中间态与完成态，确认无控制台错误、无文字溢出、无交互遮挡。
